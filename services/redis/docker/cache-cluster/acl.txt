# Test-only ACL for services/redis/docker/cache-cluster/compose.yml. The secrets are the
# user names with "-secret" appended (ci-main -> "ci-main-secret", and so
# on) and are of course not secret; the records are services/redis/docker/sccache_e2e's,
# made with `redis_gateway_node --hash-secret 10000`. The forwarding user
# is not here: the daemon appends it from KYTHIRA_REDIS_INTERNAL_SECRET.
# The same users serve RESP and HTTP (Basic or Bearer).
#
# ci-main   populates the cache: sccache over WebDAV and vcpkg's http source
# ci-pr     may only read it
# ops       is what the scenario tests use for readiness (INFO)
# iam-cache is IAM-only (auth=iam) with the secret `disabled`, as
#           doc/redis-gateway.md's rolling-upgrade rule says: an old build
#           reads auth=iam as a key prefix and refuses the disabled user,
#           and a new one has no IAM verifier here, so nobody logs in as it
