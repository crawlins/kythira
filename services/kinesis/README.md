# Kinesis module

A Kinesis Data Streams-compatible service for Kythira. Unmodified AWS SDKs,
the AWS CLI, KPL and KCL point `--endpoint-url` at a Kythira cluster. A
Kinesis shard is a routing key in Kythira's Raft groups, not a group of its
own, and record bytes live in the core record segment store, outside the
Raft snapshot. The spec is `.kiro/specs/kinesis-compatible-streams/`; this
directory follows `services/README.md`.

Built when `CONFIG_KINESIS=y` (`services/kinesis/Kconfig`, off by default).
`configs/ci_full_defconfig` turns it on, so ci.yml builds and tests it;
`configs/ci_no_kinesis_defconfig` is the module-off configuration
`.github/workflows/kinesis-module.yml` checks.

(task 2), and the Beast HTTPS server's `Expect: 100-continue` answer that
KPL waits for (task 6).

## Running a cluster

Each node needs its id, every voter's Raft URL, a data directory and a key
file; the gateways of a multi-node cluster also share a forwarding secret.
A three-node cluster on one host, plaintext, for trying it out:

```sh
printf 'AKIDEXAMPLE0001 secret0001 111122223333 ops admin\n' > keys
PEERS=1=http://127.0.0.1:7101,2=http://127.0.0.1:7102,3=http://127.0.0.1:7103
GW=1=127.0.0.1:4561,2=127.0.0.1:4562,3=127.0.0.1:4563
for i in 1 2 3; do
  KYTHIRA_NODE_ID=$i KYTHIRA_PEERS=$PEERS KYTHIRA_RAFT_BIND=127.0.0.1 \
  KYTHIRA_RAFT_PORT=710$i KINESIS_LISTEN=127.0.0.1:456$i \
  KINESIS_ALLOW_PLAINTEXT=true KINESIS_STATIC_KEYS_FILE=$PWD/keys \
  KINESIS_DATA_DIR=$PWD/n$i KINESIS_PEER_GATEWAYS=$GW \
  KINESIS_FORWARD_SECRET=change-me-shared-secret ./kinesis_gateway_node &
done
aws --endpoint-url http://127.0.0.1:4562 kinesis create-stream --stream-name s --shard-count 2
```

Any node takes any request: a write whose group this node does not lead
goes to the leader's gateway, signed with the shared secret, and a node
restoring a snapshot fetches the segments it lacks from its peers the same
way. Shard iterators are signed with a key derived from that secret, so
an iterator from one node works on every other; to rotate iterator keys
without breaking live consumers, give every gateway the same
`KINESIS_ITERATOR_KEYS_FILE` (`id secret` per line, the signing key first,
the previous one kept for at least five minutes). Off a trusted network, give each gateway `KINESIS_TLS_CERT` and
`KINESIS_TLS_KEY` and the peers' CA as `KINESIS_PEER_CA`; Raft RPC itself is
plaintext, as in `redis_gateway_node`, so `KYTHIRA_ALLOW_PLAINTEXT_RAFT` is
required off loopback.

Retention and tiering (`doc/retention.md`) need no setup: every node runs a
maintenance pass each `KINESIS_MAINTENANCE_INTERVAL_MS` (a minute), and a
shard's leader trims what is past the stream's retention period. Writes
stop with `InternalFailure` naming the disk guard when the segment disk has
less than `KINESIS_DISK_FLOOR_BYTES` free (1 GiB; 0 turns it off). To keep
long retention off local disks, set `KINESIS_TIER_AFTER_HOURS` and
`KINESIS_TIER_S3_BUCKET` (with `_PREFIX`, `_REGION` and, for an
S3-compatible store, `_ENDPOINT`); credentials come from the AWS SDK's
default chain, and a build without the SDK's s3 component refuses those
settings.

To upgrade the model, copy `botocore/data/kinesis/<version>/service-2.json`
from a newer botocore wheel over `model/service-2.json`, bump
`BOTOCORE_VERSION` in `tools/gen_operations.py`, rerun it, and place any new
operation in `implemented-operations.txt` or `doc/unsupported.md`. The
pull request carries the regenerated header's diff (Requirement 2.4).

## What a split would still need

Nothing beyond the table above: the module uses core's public headers
(`aws_json_protocol.hpp`, `sigv4_verifier.hpp`, `aws_request_authorizer.hpp`,
`static_key_authorizer.hpp`, `beast_https_server.hpp`,
`record_segment_store.hpp`), and only the daemon's `run_host.cpp` includes
the multi-raft and Beast transport `*_impl.hpp` headers
(`boundary-allow.txt`).
