# The IAM and STS calls the Terraform AWS provider makes, recorded against
# real AWS (.kiro/specs/iam-compatible-auth/ task 15).
#
# Recorded 2026-11-10 with Terraform 1.17.1 and hashicorp/aws 6.72.0
# (aws-sdk-go-v2 1.47.4, IAM client 1.64.5), IAM only, in a scratch
# account path, from the Action= of every request body in the debug logs.
# The configuration covered users (with tags, inline policy, attachment
# and permissions boundary), an access key, two groups with membership,
# inline and attached policies, a customer managed policy with a second
# version, roles with tags, inline policies, attachments and a boundary,
# an instance profile and an OIDC provider. Phases: apply; an update
# apply (new policy version, changed role and user tags); plan with
# -detailed-exitcode; destroy. Every resource was deleted afterwards.
#
# Format: <Action> <total calls> <phases>, where the phases are a(pply),
# u(pdate), p(lan) and d(estroy). Every action here is implemented
# (doc/iam.md); the conformance job (iam_conformance_test) applies,
# re-plans and destroys services/iam/tests/docker/conformance/terraform/
# against Kythira and fails on any NotImplemented.
#
# The provider never called: Tag*/List*Tags on create (tags ride in the
# Create* call and are read back from Get*), Put{User,Role}PermissionsBoundary
# (the boundary rides in CreateUser/CreateRole), TagPolicy, UpdateRole,
# UpdateAssumeRolePolicy, or any OIDC provider update. Kythira implements
# them anyway, for other configurations.
#
# Observed provider behaviour worth knowing:
# - aws_iam_policy_attachment is exclusive: on update it detaches every
#   other holder of the policy (DetachRolePolicy/DetachUserPolicy), and
#   its ListEntitiesForPolicy read takes no usage filter, so a user that
#   holds the policy only as a boundary is pulled into its state. The
#   conformance config uses the per-entity attachment resources instead.
# - Deleting that drifted state, AWS answered DetachUserPolicy for an
#   already-deleted user with 403, not NoSuchEntity; a second destroy
#   finished.
